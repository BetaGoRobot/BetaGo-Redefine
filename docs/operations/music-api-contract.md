# BetaGo Music API v1 — implemented contract (2026-11-13)

Base: `/music-api/v1`, JSON, same origin. Times RFC3339 with explicit timezone offset; durationMs and positionMs milliseconds. No browser NetEase login, QR, owner_id or client-supplied music-account cookie. An optional existing operator-held source authorization remains server-side and never defines application identity. Unknown JSON fields rejected on writes. Errors `{ "error": "..." }`, 400 invalid, 401 session expired, 404 inaccessible/deleted/revoked, 409 stale revision, 403 source access denied, 502 invalid trusted-cache data, 503 provider unavailable.

## Identity
- Public `GET /auth/options` → `{guest:true,feishu:{enabled:boolean,appID:string}}`. No session required and no session issued. `enabled` requires an explicit application ID plus a server verifier; disabled responses expose an empty appID. This describes server configuration, not proof of approved client permissions or domains. No application secret, provider token, user identity, or session credential is exposed.
- `POST /auth/guest {}` → `{user:{id,kind:"guest"}, expiresAt}` + HttpOnly SameSite=Lax music_session cookie (30d). Repeated call with valid session reuses it.
- Non-browser clients: `POST /auth/guest {"transport":"bearer"}` → also `sessionToken`; keep in platform secure storage, send `Authorization: Bearer <token>`. Never put browser cookies or tokens in URLs. All credentials SHA256 hashed server-side.
- `GET /me` → `{user:{id,kind}, expiresAt}`. `POST /auth/logout {}` revokes current session.
- `POST /auth/recovery {}` → `{recoveryCode}` rotates a separate high entropy recovery secret (shown once). `POST /auth/recover {recoveryCode,transport?}` → own session. Recovery restores the same guest library on another device; keep secret, rotate to invalidate old code. JSON export/import instead copies a library. Guest browsing does NOT provide automatic private cross-device identity.
- `POST /auth/feishu/exchange {code,transport?}` → own session only after backend code exchange and `/authen/v1/user_info` verification. Optional deployment configuration; missing configuration → 503 `feishu_not_configured`, rejected temporary code → 401 `feishu_code_rejected`; guest remains usable. Server derives appID, actual tenant_key and subject, never trusts URL open_id. Applications and real tenants are separate boundaries.

## Tracks / sources
Stable ID is a string `source:externalID`, e.g. `netease:186016` or `kuwo:629335603`; never song title or hardcoded numeric placeholder. URL-encode ID as path component. Metadata `{id,source,externalID,title,artist,album,picture,durationMs}`. No temporary playback URLs in stored metadata/export.
- `GET /catalog/options` → `{defaultSource:"netease",sources:[{id:"netease",name:"网易云"},{id:"kuwo",name:"酷我"}]}`. Public configuration discovery, no identity, endpoint or secret. Kuwo appears only when `MUSIC_KUWO_API_URL` is explicitly configured; this is not a claim every recording is available.
- `GET /search?q=...&source=kuwo` → `{tracks:[Track]}` for the explicitly selected configured source. Omitting source preserves the existing NetEase default. Unknown/unconfigured source is 400. Source discovery/selection never changes an already queued recording or personal identity; failed searches never fall through to another source.
- `POST /tracks/details {ids:["netease:186016"]}` → `{tracks:[Track]}`.
- `GET /tracks/{id}` → Track.
- Public `GET /tracks/{id}/artwork` → 307 to a newly signed HTTPS image, or 404 if absent. Only the configured music bucket’s fixed `picture/<numericID>.jpg` is accessible. No arbitrary URL, short-link following, object path, or private non-music bucket is accepted. Track picture fields contain this stable HTTPS entry instead of a persisted image signature. All Track JSON output, including old verified playlists/likes/history/export, upgrades only p1/p2/p3/p4.music.126.net HTTP artwork to HTTPS and blanks other HTTP artwork.
- `GET /tracks/{id}/lyrics` → `{trackID, lrc, translatedLrc}` asynchronously per track. Client discards stale results on track change.
- `POST /tracks/{id}/resolve {}` → `{trackID,status:"available"|"preview"|"unavailable",url?,expiresAt?,reason?}`. Re-resolved temporary URL, explicit configured source priority and no cross-recording/source substitution. expiresAt is provider expiry or a conservative local recheck deadline (NetEase at most 5 min, direct Kuwo at most 2 min; owned MinIO signatures 300 seconds). A local deadline does not assert the upstream signed URL will remain valid until that instant. Preview must be labelled; unavailable has no URL. On media error/expiry refresh ONCE per selected track, restore progress after load, then stop with visible reason; never infinite retry or silent skip. Autoplay rejection requires explicit user action.
- Legacy `?target=<full descriptor URL>` handled by client asynchronous fetch. If descriptor has TrackID/Source/ExternalID use it; old `info/<numericID>.json` infers `netease:<numericID>`. Other descriptors use `legacy:<SHA256 descriptor URL>` and temporary in-memory URLs only; expired legacy descriptor requires reopening a fresh card.

## Library
- `GET /playlists` → `{playlists:[{id,name,revision,tracks:[Track]}]}`.
- `POST /playlists {name,trackIDs?:[]}` → Playlist.
- `GET /playlists/{id}` → Playlist.
- `PUT /playlists/{id} {name,trackIDs:[],revision}` → Playlist. Complete ordered list, deduplicates stable IDs. Transaction + compare-and-swap, stale 409. `DELETE /playlists/{id} {revision}` tombstones; no upsert resurrection.
- `GET /likes` → `{tracks:[Track]}`; `PUT /likes/{trackID} {}`; `DELETE /likes/{trackID}`.
- `GET /history` → `{history:[{track:Track,positionMs,playedAt}]}` (most recent 200); `POST /history {trackID,positionMs}`; `DELETE /history`.

## Device queue
`GET /queue/{deviceID}` → `{revision:0,trackIDs:[],currentIndex:0,positionMs:0}` for new device.
`PUT /queue/{deviceID} {revision,trackIDs:[],currentIndex,positionMs}` → updated snapshot with revision+1. Allows duplicate tracks (position identifies occurrence). Max 1000 items. CAS 409, never blindly retry overwrite. Queue owner from own session; deviceID (random UUID persisted locally) is NOT a credential. Refresh restores paused at position and re-resolves source; no audio URL in queue. Mini-program creates its own bearer session/device or deliberately uses recovery flow, never imports web cookie.

## Sharing / transfer
- `POST /shares {kind:"playlist"|"track",targetID}` → `{id,token}`. Token shown once, stored hashed. Default 30d readonly. Owner can list `GET /shares` (no tokens), revoke `DELETE /shares/{id}`.
- `GET /shared/{token}` → versioned export subset `{format:"betago-music",version:1,playlists:[{name,tracks:[Track]}],likes:[]}`. No owner/session/history/queue. Current playlist state until deletion/revoke/expiry; 404 afterward. Single track uses one-item playlist. Public read only, no mutation capability.
- `POST /shared/{token}/copy {}` authenticated → new playlist owned by caller.
- `GET /export` → `{format:"betago-music",version:1,playlists:[{name,tracks:[Track]}],likes:[Track]}`. No cookie/recovery/session secret/audio URL.
- `POST /import <same export object>` → `{imported:<playlist count>}`. Transactional; creates copies, never accepts owner IDs or overwrites existing playlists. Max 1000 tracks per playlist / 50 playlists / 2 MiB. Source IDs validated; metadata is read from the configured server provider or a previously verified catalogue row. Client JSON metadata is reference data only and cannot seed or overwrite the shared catalogue. An unavailable provider may reject an import of uncached recordings with 503; the transaction makes no partial copy.

Preview address and actual verified source/Feishu support recorded separately in acceptance report. This contract belongs to betago-music-web; mini task may read, must not edit it.

Implementation addition: `POST /tracks/register {track:Track}` accepts a legacy descriptor identity and verifies `id === source + ':' + externalID`; URLs/lyricsURL/owner fields are not accepted. Submitted title/artist/album/picture/duration are ignored: the response and shared cache use the configured server provider's canonical metadata (or a previously verified row). Unsupported source IDs are rejected for new persistence; an unidentified legacy descriptor may still be played in client memory, with persistence explicitly unavailable. Existing unsupported metadata remains in its owners' already saved exports, but is not available through generic track lookup or a new ownership claim. Old unverified known-source rows are repaired on lookup instead of shadowing provider results permanently. New card descriptors include TrackID/Source/ExternalID. During a provider 503 only, a still-valid old descriptor may play its exact in-memory URL; an explicit provider restriction/unavailable result never falls back. The same finite retry budget applies.

Anonymous NetEase resolution compatibility: if `/song/url/v1` fails at the transport/decoder level, the adapter tries `/song/url` once for the same external ID at 128 kbps. A valid restricted/unavailable/preview v1 response is final and never falls through. Both endpoints use `unblock=false`; default requests carry no cookies. Optional `MUSIC_NETEASE_COOKIE` is sent only as a server-side Cookie header to the configured trusted API, with redirects disabled; it is never a query parameter, client input, personal application identity or response field; client recovery remains limited to one re-resolution.

Media provenance: the anonymous NetEase adapter rejects non-NetEase audio hosts with `status:"unavailable", reason:"source_mismatch: ..."`, even when an upstream API returns the requested numerical ID. This prevents a deployed unblock/matching proxy from silently substituting a different source despite `unblock=false`. No third-party music host is permitted by default. HTTP official audio URLs are upgraded only after an independent credential-free HTTPS HEAD check (one bounded one-byte Range GET when HEAD does not confirm access, including CDNs that reject HEAD while permitting that exact GET); failure returns unavailable. Optional legacy exact-host proxy configuration does not authorize writing a nonofficial recording into the owned cache.

Canonical catalogue upgrade: apply additive `20261113_music_canonical.sql` after the original music tables. It defaults old rows to unverified and never drops personal records. `MUSIC_MIGRATE=false` startup requires this column. Metadata registration preserves explicit upstream HTTP401/403 as HTTP403 `source_access_denied`. During resolution, all explicit HTTP401/403 denials, including the compatibility endpoint, and per-recording non-success codes return unavailable without a URL; none are classified as a recoverable transport outage.


## Explicit owned MinIO cache and write-through
With `MUSIC_MINIO_CACHE_ENABLED=true`, the server independently checks trusted fixed same-ID objects before the catalogue adapter. It reads `catalog/<numericID>.json` v1 manifests or existing `info/<numericID>.json`, verifies identity and a nonempty `music/<numericID>.mp3`, and re-signs a GET for the configured HTTPS public origin. Result: `status:"available", reason:"owned_minio_cache", expiresAt` (300-second signature expiry). Old descriptor MusicURL/audioURL/LyricsURL are never followed; lyrics come from inline data or fixed `lyrics/<id>.json` / `.txt`. Only object absence delegates to the configured same-ID source. Denial, malformed data or cache outages remain explicit; an owned cache is an operator-enabled independent source, not a hidden retry after an upstream restriction.

With additional `MUSIC_MINIO_CACHE_WRITE_ENABLED=true`, a cache miss resolving to a complete `available` official HTTPS recording can fill the cache. Same-ID concurrent calls are coalesced in the API process, at most two writers run, each operation has a 12-second bound within the request deadline and a 64 MiB audio limit. Downloads send no source cookie/authorization and never follow redirects. Before downloading, an existing audio object without trustworthy catalogue/info metadata is preserved with `cache_skipped_existing_unverified_audio` (no download or PUT); stat errors skip caching. Every new PUT uses `If-None-Match:*` to prevent concurrent overwrites. HTTP200 error pages and non-MP3 content are rejected by MIME plus ID3/MPEG header checks with `cache_failed_format`; they are not written as mp3. A complete audio PUT precedes optional canonical lyrics and a final `catalog/<id>.json` commit manifest. The manifest contains version, stable identity, trusted metadata, fixed object key and timestamp; no audio URL or credential. Successful first fill returns `owned_minio_cache_stored`; later plays use `owned_minio_cache`. Failed writes keep the legal source URL playable with a `cache_failed_*` reason, and overload reports `cache_busy`; neither claims persistence. Preview results keep status preview with `cache_skipped_preview` and are not cached as full recordings. Unavailable/restricted results are not cached. Existing old info objects are never overwritten by this writer. Real provider/MinIO runtime evidence is recorded separately from fixture-based regression tests.


## Explicit additional source (Kuwo)

The independent `KuwoProvider` uses the repository-contained read-only loopback service `deploy/music-sources/alternative-source.cjs` with its vendored codec/licenses (workspace alias: `tools/alternative-source.cjs`). It accepts exact numeric `kuwo:<externalID>` identities only. Metadata comes from official public search and a bounded verified catalogue index; a persisted index is needed to reopen previously searched IDs after source-service restart when the public detail endpoint is unavailable. Resolve rechecks the exact ID and public rights, never matches a NetEase ID or silently picks the same song title. Version text (Live/Edit/伴奏 etc.), artist, album and duration remain visible; unknown version is not asserted to be the original recording.

Direct source URLs require official Kuwo HTTPS, actual certificate/Range verification and MPEG duration checks. Restricted/unknown rights and a short or unrecognized resource are unavailable without URL; an explicitly identified preview must retain preview status. Kuwo lyrics currently return empty text for the same exact track ID, never another recording's lyrics. Application cookies and source-account credentials never reach this service. Only configured local endpoints are accepted by the Go adapter.

When the explicitly enabled owned MinIO reader/writer wraps Kuwo, fixed objects use separate namespaces: `music/kuwo/<id>.mp3`, `catalog/kuwo/<id>.json`, `lyrics/kuwo/<id>.json` and `picture/kuwo/<id>.jpg`. NetEase keeps its existing `music/<id>.mp3`, `catalog/<id>.json`, `lyrics/<id>.json`, `picture/<id>.jpg` and legacy `info/<id>.json` layout. Kuwo never imports NetEase's legacy info object. The public artwork API stays `/tracks/{source:externalID}/artwork`; the source router selects fixed `picture/kuwo/<id>.jpg` for Kuwo and `picture/<id>.jpg` for NetEase before issuing a fresh HTTPS redirect. Each manifest's source/stable ID/object path must agree; the same numeric ID on different platforms cannot collide. Both sources share the module's two-writer bound, and each writer permits only its own official CDN hosts. A successful Kuwo write is claimed only after the final namespaced commit manifest is stored; configuration or fixture tests alone are not runtime storage evidence.

Frontend source selection is explicit, defaults to NetEase and invalidates stale search responses when the user changes platforms. Track lists show source labels; queue, personal library, sharing and export preserve literal source-prefixed IDs. New source routing does not trust `open_id`, `owner_id` or arbitrary provider URLs from the browser. Real Kuwo source and MinIO deployment acceptance is recorded separately in `audio-source-expansion.md` and runtime evidence.
