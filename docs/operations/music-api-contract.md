# BetaGo Music API v1 — implemented contract (2026-11-13)

Updated 2026-11-16: UNM provenance, private search history, interest recommendations and anonymous public-playlist import are additive extensions below.

Base: `/music-api/v1`, JSON, same origin. Times RFC3339 with explicit timezone offset; durationMs and positionMs milliseconds. No browser NetEase login, QR, owner_id or client-supplied music-account cookie. An optional existing operator-held source authorization remains server-side and never defines application identity. Unknown JSON fields rejected on writes. Errors `{ "error": "..." }`, 400 invalid, 401 session expired, 404 inaccessible/deleted/revoked, 409 stale revision, 403 source access denied, 502 invalid trusted-cache data, 503 provider unavailable.

## Identity
- Public `GET /auth/options` → `{guest:true,feishu:{enabled:boolean,appID:string}}`. No session required and no session issued. `enabled` requires an explicit application ID plus a server verifier; disabled responses expose an empty appID. This describes server configuration, not proof of approved client permissions or domains. No application secret, provider token, user identity, or session credential is exposed.
- `POST /auth/guest {}` → `{user:{id,kind:"guest"}, expiresAt}` + HttpOnly SameSite=Lax music_session cookie (30d). Repeated call with valid session reuses it.
- Non-browser clients: `POST /auth/guest {"transport":"bearer"}` → also `sessionToken`; keep in platform secure storage, send `Authorization: Bearer <token>`. Never put browser cookies or tokens in URLs. All credentials SHA256 hashed server-side.
- `GET /me` → `{user:{id,kind,displayName,avatarURL,profileUpdatedAt,profileNeedsRefresh}, expiresAt}` for the current account only. New profile fields are backward-compatible additions: empty displayName/avatarURL strings mean unavailable, profileUpdatedAt is an RFC3339 timestamp or null, and profileNeedsRefresh is true only for a Feishu account with no recorded verified profile attempt. `POST /auth/logout {}` revokes current session.
- `POST /auth/recovery {}` → `{recoveryCode}` rotates a separate high entropy recovery secret (shown once). `POST /auth/recover {recoveryCode,transport?}` → own session. Recovery restores the same guest library on another device; keep secret, rotate to invalidate old code. JSON export/import instead copies a library. Guest browsing does NOT provide automatic private cross-device identity.
- `POST /auth/feishu/exchange {code,transport?}` → own session only after backend code exchange and `/authen/v1/user_info` verification. Optional deployment configuration; missing configuration → 503 `feishu_not_configured`, rejected temporary code → 401 `feishu_code_rejected`; guest remains usable. Server derives appID, actual tenant_key and subject, never trusts URL open_id. Applications and real tenants are separate boundaries.

## Tracks / sources
Stable ID is a string `source:externalID`, e.g. `netease:186016` or `kuwo:629335603`; never song title or hardcoded numeric placeholder. URL-encode ID as path component. Metadata `{id,source,externalID,title,artist,album,picture,durationMs}`. No temporary playback URLs in stored metadata/export.
- `GET /catalog/options` → `{defaultSource:"netease",sources:[{id:"netease",name:"网易云"},{id:"kuwo",name:"酷我"}]}`. Public configuration discovery, no identity, endpoint or secret. Kuwo appears only when `MUSIC_KUWO_API_URL` is explicitly configured; this is not a claim every recording is available.
- `GET /search?q=...&source=kuwo` → `{tracks:[Track]}` for the explicitly selected configured source. Omitting source preserves the existing NetEase default. Unknown/unconfigured source is 400. Source discovery/selection never changes an already queued recording or personal identity; failed searches never fall through to another source.
- `POST /tracks/details {ids:["netease:186016"]}` → `{tracks:[Track]}`.
- `GET /tracks/{id}` → Track.
- Public `GET /tracks/{id}/artwork` → 307 to a newly signed HTTPS image, or 404 if absent. Only the configured music bucket’s fixed `picture/<numericID>.jpg` is accessible. No arbitrary URL, short-link following, object path, or private non-music bucket is accepted. Track picture fields contain this stable HTTPS entry instead of a persisted image signature. All Track JSON output, including old verified playlists/likes/history/export, upgrades only p1/p2/p3/p4.music.126.net HTTP artwork to HTTPS and blanks other HTTP artwork.
- `GET /tracks/{id}/lyrics` → `{trackID, lrc, translatedLrc}` asynchronously per track. Client discards stale results on track change.
- `POST /tracks/{id}/resolve {}` → `{trackID,status:"available"|"preview"|"unavailable",url?,expiresAt?,reason?,mediaSource?,originTrackID?,matchMethod?,verification?}`. Re-resolved temporary URL, explicit configured source priority and no cross-recording/source substitution. expiresAt is provider expiry or a conservative local recheck deadline (NetEase at most 5 min, direct Kuwo at most 2 min; owned MinIO signatures 300 seconds). A local deadline does not assert the upstream signed URL will remain valid until that instant. Preview must be labelled; unavailable has no URL. On media error/expiry refresh ONCE per selected track, restore progress after load, then stop with visible reason; never infinite retry or silent skip. Autoplay rejection requires explicit user action.
- Legacy `?target=<full descriptor URL>` handled by client asynchronous fetch. If descriptor has TrackID/Source/ExternalID use it; old `info/<numericID>.json` infers `netease:<numericID>`. Other descriptors use `legacy:<SHA256 descriptor URL>` and temporary in-memory URLs only; expired legacy descriptor requires reopening a fresh card.

## Library
- `GET /playlists` → `{playlists:[{id,name,revision,tracks:[Track]}]}`.
- `POST /playlists {name,trackIDs?:[]}` → Playlist.
- `GET /playlists/{id}` → Playlist.
- `PUT /playlists/{id} {name,trackIDs:[],revision}` → Playlist. Complete ordered list, deduplicates stable IDs. Transaction + compare-and-swap, stale 409. `DELETE /playlists/{id} {revision}` tombstones; no upsert resurrection.
- `GET /likes` → `{tracks:[Track]}`; `PUT /likes/{trackID} {}`; `DELETE /likes/{trackID}`.
- `GET /history` → `{history:[{track:Track,positionMs,playedAt}]}` (most recent 200); `POST /history {trackID,positionMs}`; `DELETE /history`.

## Device queue
`GET /queue/{deviceID}` → `{revision:0,trackIDs:[],currentIndex:0,positionMs:0}` for new device.
`PUT /queue/{deviceID} {revision,trackIDs:[],currentIndex,positionMs}` → updated snapshot with revision+1. Allows duplicate tracks (position identifies occurrence). Max 1000 items. CAS 409, never blindly retry overwrite. Queue owner from own session; deviceID (random UUID persisted locally) is NOT a credential. Refresh restores paused at position and re-resolves source; no audio URL in queue. Mini-program creates its own bearer session/device or deliberately uses recovery flow, never imports web cookie.

## Sharing / transfer
- `POST /shares {kind:"playlist"|"track",targetID}` → `{id,token}`. Token shown once, stored hashed. Default 30d readonly. Owner can list `GET /shares` (no tokens), revoke `DELETE /shares/{id}`.
- `GET /shared/{token}` → versioned export subset `{format:"betago-music",version:1,playlists:[{name,tracks:[Track]}],likes:[]}`. No owner/session/history/queue. Current playlist state until deletion/revoke/expiry; 404 afterward. Single track uses one-item playlist. Public read only, no mutation capability.
- `POST /shared/{token}/copy {}` authenticated → new playlist owned by caller.
- `GET /export` → `{format:"betago-music",version:1,playlists:[{name,tracks:[Track]}],likes:[Track]}`. No cookie/recovery/session secret/audio URL.
- `POST /import <same export object>` → `{imported:<playlist count>}`. Transactional; creates copies, never accepts owner IDs or overwrites existing playlists. Max 1000 tracks per playlist / 50 playlists / 2 MiB. Source IDs validated; metadata is read from the configured server provider or a previously verified catalogue row. Client JSON metadata is reference data only and cannot seed or overwrite the shared catalogue. An unavailable provider may reject an import of uncached recordings with 503; the transaction makes no partial copy.

Preview address and actual verified source/Feishu support recorded separately in acceptance report. This contract belongs to betago-music-web; mini task may read, must not edit it.

Implementation addition: `POST /tracks/register {track:Track}` accepts a legacy descriptor identity and verifies `id === source + ':' + externalID`; URLs/lyricsURL/owner fields are not accepted. Submitted title/artist/album/picture/duration are ignored: the response and shared cache use the configured server provider's canonical metadata (or a previously verified row). Unsupported source IDs are rejected for new persistence; an unidentified legacy descriptor may still be played in client memory, with persistence explicitly unavailable. Existing unsupported metadata remains in its owners' already saved exports, but is not available through generic track lookup or a new ownership claim. Old unverified known-source rows are repaired on lookup instead of shadowing provider results permanently. New card descriptors include TrackID/Source/ExternalID. During a provider 503 only, a still-valid old descriptor may play its exact in-memory URL; an explicit provider restriction/unavailable result never falls back. The same finite retry budget applies.

Anonymous NetEase resolution compatibility: if `/song/url/v1` fails at the transport/decoder level, the adapter tries `/song/url` once for the same external ID at 128 kbps. A valid restricted/unavailable/preview v1 response never falls through to the transport compatibility endpoint; only the separately defined eligible account stage may follow. Both endpoints use `unblock=false`; catalogue search/detail/lyrics and the anonymous playback stage carry no cookies. Optional `MUSIC_NETEASE_COOKIE` is reserved for the bounded final playback stage, described below; it is never a query parameter, client input, personal application identity or response field. Client recovery remains limited to one re-resolution.

NetEase playback priority, when explicitly configured: existing owned MinIO (legacy official objects first, then a committed UNM namespace) → official loopback UNM bridge `/pyncmd/check` with the original NetEase numeric ID → anonymous same-ID NetEase → authorized same-ID account fallback. `MUSIC_UNM_BRIDGE_URL` is optional and loopback only. Search/detail/lyrics remain anonymous; Kuwo remains a separately selected catalogue and is never an automatic replacement. The generic UNM title-matching providers are not invoked.

Account eligibility requires a syntactically valid successful anonymous response with exactly the requested ID and per-item code 0/200, containing either an empty URL or an explicitly labelled preview. HTTP 401/403/429, transport/decoder errors, other item codes, wrong IDs and unapproved hosts do not qualify. A bridge failure is unclassified and can only advance to the anonymous stage; it is never itself account eligibility. An account attempt calls only `/song/url/v1` once, with a 10-second deadline; anonymous transport compatibility is at most one `/song/url` call. Each process limits account starts to 12/minute and 2 concurrent independently of MinIO write configuration; concurrent same-ID work is coalesced. Failed account/UNM resolutions and final unavailable outcomes have bounded 15-second negative caches (at most 512 keys each, no URLs); UNM has 2 concurrent slots, a 6-second request/probe deadline and no redirect/retry. The whole source pipeline has a 30-second deadline. If account fallback fails, a legitimate anonymous preview remains available and labelled.

Resolution provenance fields are optional strings for backward compatibility: `mediaSource` is `unm:pyncmd`, `netease:anonymous` or `netease:account`; `originTrackID` remains the original stable `netease:<id>`; `matchMethod` is `provider_external_id`. `verification:"audio_prefix"` means only an HTTPS audio Range prefix was checked; `verification:"id_and_duration"` means a complete MP3 frame stream had a duration close to the canonical original-ID metadata. Neither proves identical recording/version or an audio fingerprint match. Official provider resolutions use `verification:"provider_id"`. Legacy cache objects without recorded provenance leave these fields absent. MinIO cache hits retain the manifest's original `mediaSource`, while `reason:owned_minio_cache` describes delivery. These playback fields and temporary URLs are not personal-library Track fields or JSON export data.

UNM direct URLs have a conservative recheck deadline of at most 120 seconds and must be credential-free HTTPS on exact NetEase music-domain boundaries, standard port, no redirects. A 206 Range with consistent length, MIME and MP3 prefix is required. A complete UNM cache write additionally requires a bounded (64 MiB/12 seconds), nonpartial full MP3 stream and canonical duration within max(1.5 seconds, 3%), capped at 5 seconds. Short complete streams are labelled preview; malformed/truncated or mismatched streams are unavailable. No incomplete or preview audio is committed. UNM objects use only `music/unm/pyncmd/netease/<id>.mp3`, `catalog/unm/pyncmd/netease/<id>.json` and `lyrics/unm/pyncmd/netease/<id>.json`; manifest v2 records canonical Track, exact object path, source provenance, measured duration, byte length and SHA-256, without temporary media URL or credentials. The manifest is the immutable commit marker. Restart lookup validates its ID/source/path/provenance and audio length before signing. Existing NetEase flat paths and Kuwo paths remain unchanged; unverified orphan objects are never overwritten or exposed as hits.

Media provenance: the anonymous NetEase adapter rejects non-NetEase audio hosts with `status:"unavailable", reason:"source_mismatch: ..."`, even when an upstream API returns the requested numerical ID. This prevents a deployed unblock/matching proxy from silently substituting a different source despite `unblock=false`. No third-party music host is permitted by default. HTTP official audio URLs are upgraded only after an independent credential-free HTTPS HEAD check (one bounded one-byte Range GET when HEAD does not confirm access, including CDNs that reject HEAD while permitting that exact GET); failure returns unavailable. Optional legacy exact-host proxy configuration does not authorize writing a nonofficial recording into the owned cache.

Canonical catalogue upgrade: apply additive `20261113_music_canonical.sql` after the original music tables. It defaults old rows to unverified and never drops personal records. `MUSIC_MIGRATE=false` startup requires this column. Metadata registration preserves explicit upstream HTTP401/403 as HTTP403 `source_access_denied`. During resolution, all explicit HTTP401/403 denials, including the compatibility endpoint, and per-recording non-success codes return unavailable without a URL; none are classified as a recoverable transport outage.


## Explicit owned MinIO cache and write-through
With `MUSIC_MINIO_CACHE_ENABLED=true`, the server independently checks trusted fixed same-ID objects before the catalogue adapter. It reads `catalog/<numericID>.json` v1 manifests or existing `info/<numericID>.json`, verifies identity and a nonempty `music/<numericID>.mp3`, and re-signs a GET for the configured HTTPS public origin. Result: `status:"available", reason:"owned_minio_cache", expiresAt` (300-second signature expiry). Old descriptor MusicURL/audioURL/LyricsURL are never followed; lyrics come from inline data or fixed `lyrics/<id>.json` / `.txt`. Only object absence delegates to the configured same-ID source. Denial, malformed data or cache outages remain explicit; an owned cache is an operator-enabled independent source, not a hidden retry after an upstream restriction.

With additional `MUSIC_MINIO_CACHE_WRITE_ENABLED=true`, a cache miss resolving to a complete `available` official HTTPS recording can fill the cache. Same-ID concurrent calls are coalesced in the API process, at most two writers run, each operation has a 12-second bound within the request deadline and a 64 MiB audio limit. Downloads send no source cookie/authorization and never follow redirects. Before downloading, an existing audio object without trustworthy catalogue/info metadata is preserved with `cache_skipped_existing_unverified_audio` (no download or PUT); stat errors skip caching. Every new PUT uses `If-None-Match:*` to prevent concurrent overwrites. HTTP200 error pages and non-MP3 content are rejected by MIME plus ID3/MPEG header checks with `cache_failed_format`; they are not written as mp3. A complete audio PUT precedes optional canonical lyrics and a final `catalog/<id>.json` commit manifest. The manifest contains version, stable identity, trusted metadata, fixed object key and timestamp; no audio URL or credential. Successful first fill returns `owned_minio_cache_stored`; later plays use `owned_minio_cache`. Failed writes keep the legal source URL playable with a `cache_failed_*` reason, and overload reports `cache_busy`; neither claims persistence. Preview results keep status preview with `cache_skipped_preview` and are not cached as full recordings. Unavailable/restricted results are not cached. Existing old info objects are never overwritten by this writer. Real provider/MinIO runtime evidence is recorded separately from fixture-based regression tests.


## Explicit additional source (Kuwo)

The independent `KuwoProvider` uses the repository-contained read-only loopback service `deploy/music-sources/alternative-source.cjs` with its vendored codec/licenses (workspace alias: `tools/alternative-source.cjs`). It accepts exact numeric `kuwo:<externalID>` identities only. Metadata comes from official public search and a bounded verified catalogue index; a persisted index is needed to reopen previously searched IDs after source-service restart when the public detail endpoint is unavailable. Resolve rechecks the exact ID and public rights, never matches a NetEase ID or silently picks the same song title. Version text (Live/Edit/伴奏 etc.), artist, album and duration remain visible; unknown version is not asserted to be the original recording.

Direct source URLs require official Kuwo HTTPS, actual certificate/Range verification and MPEG duration checks. Restricted/unknown rights and a short or unrecognized resource are unavailable without URL; an explicitly identified preview must retain preview status. Kuwo lyrics currently return empty text for the same exact track ID, never another recording's lyrics. Application cookies and source-account credentials never reach this service. Only configured local endpoints are accepted by the Go adapter.

When the explicitly enabled owned MinIO reader/writer wraps Kuwo, fixed objects use separate namespaces: `music/kuwo/<id>.mp3`, `catalog/kuwo/<id>.json`, `lyrics/kuwo/<id>.json` and `picture/kuwo/<id>.jpg`. NetEase keeps its existing `music/<id>.mp3`, `catalog/<id>.json`, `lyrics/<id>.json`, `picture/<id>.jpg` and legacy `info/<id>.json` layout. Kuwo never imports NetEase's legacy info object. The public artwork API stays `/tracks/{source:externalID}/artwork`; the source router selects fixed `picture/kuwo/<id>.jpg` for Kuwo and `picture/<id>.jpg` for NetEase before issuing a fresh HTTPS redirect. Each manifest's source/stable ID/object path must agree; the same numeric ID on different platforms cannot collide. Both sources share the module's two-writer bound, and each writer permits only its own official CDN hosts. A successful Kuwo write is claimed only after the final namespaced commit manifest is stored; configuration or fixture tests alone are not runtime storage evidence.

Frontend source selection is explicit, defaults to NetEase and invalidates stale search responses when the user changes platforms. Track lists show source labels; queue, personal library, sharing and export preserve literal source-prefixed IDs. New source routing does not trust `open_id`, `owner_id` or arbitrary provider URLs from the browser. Real Kuwo source and MinIO deployment acceptance is recorded separately in `audio-source-expansion.md` and runtime evidence.


## Feishu H5 code exchange (v3)

`POST /auth/feishu/exchange {code}` continues to accept only a fresh, one-use H5 JSAPI code, never a browser-supplied owner/open_id/tenant. The server sends a form-urlencoded `authorization_code` exchange to `https://accounts.feishu.cn/oauth/v3/token` with its own App ID/Secret, then obtains canonical `tenant_key` and `open_id` from `https://open.feishu.cn/open-apis/authen/v1/user_info`. This confidential-client flow does not initiate PKCE or a browser OAuth redirect, so no invented `code_verifier` or fixed `redirect_uri` is sent. The legacy RedirectURI configuration field remains accepted but unused by H5 exchange. A future external-browser OAuth callback would require its own bound redirect/state handling; it is not provided by this endpoint.

Both upstream requests reject redirects and use a copied finite-timeout client without the caller's cookie jar. No temporary code, Feishu token or App Secret is exposed or persisted. H5 login scopes remain `[]` (basic user identity only). `requestAccess`/`requestAuthCode` are exempt from JSAPI config authentication, but the code-request page must be registered as its exact full URL under the app's **Security Settings > Redirect URLs**. Remove query/hash when registering; root-path registration does not authorize every SPA route. SDK readiness, approved webpage capability and app availability still require actual Feishu-client validation. Protocol tests alone are not successful real H5 login evidence.


## Verified basic display profile

Successful Feishu login stores only the verified `user_info` name/English-name fallback and a safe HTTPS avatar. Avatar preference is `avatar_thumb`, then `avatar_url`, then `avatar_middle`; unsafe candidates are skipped, never upgraded from HTTP or accepted from client JSON. Names have whitespace/control characters normalized and are bounded to 200 Unicode characters. No email, mobile, contacts, upstream access token or refresh token is stored. The app+actual-tenant+subject identity key and existing personal-data ownership remain unchanged. Display fields are private account data: they appear only in the account's own session/me responses, never in music export or public sharing.

`POST /auth/feishu/profile {"code":"<fresh H5 code>"}` refreshes an existing Feishu account's profile. It requires the current application's own valid Feishu session and a fresh verified temporary code for exactly the same configured App ID, actual tenant_key and open_id as that account. Guest sessions return 403 `feishu_session_required`; mismatched identity returns 403 `profile_identity_mismatch`; rejected code returns 401 `feishu_code_rejected`; unavailable verifier returns 503 `feishu_not_configured`. Unknown fields, including displayName/avatarURL/owner_id/open_id, are rejected with 400. This endpoint does not create, switch, rotate or extend an account/session: its response is `{user:SessionUser,expiresAt:<unchanged existing expiry>}`, with no Set-Cookie or new sessionToken. RFC3339 offsets may differ from the initial login representation while denoting the same expiration instant; refresh uses the same representation as current `/me`.

Old Feishu rows start with profileUpdatedAt=null and profileNeedsRefresh=true. A successful verified read always stamps profileUpdatedAt, even if name and all valid avatar candidates are empty, preventing a profile refresh loop. The client may retain its own cooldown after a failed attempt and offer manual retry; failure preserves the old profile and session. This is H5 identity refresh, not a request for additional permissions or a token-refresh loop.

Apply additive `script/sql/20261116_music_profile.sql` after the original and canonical music migrations. It adds display_name, avatar_url and nullable profile_updated_at only; no original SQL checksum, identity, recovery credential, account ID, session hash or expiry is changed. The same file is registered in standalone Migrate and the standard migration registry. `MUSIC_MIGRATE=false` startup requires all three columns; the migration is repeatable without clearing saved profiles or personal libraries.

## Private search history and interest recommendations

- `GET /search-history?limit=20` → `{searches:[{query,source,count,lastSearchedAt}]}`, newest first. Limit1–100. Requires own session; no owner parameter.
- `POST /search-history {query,source}` records an **explicit user search**. Source defaults to netease and must be configured. Queries are normalized, limited to200 Unicode characters/800bytes, coalesced case-insensitively per owner+source, and counted. Retains the most recent100 distinct searches per owner. Owner-scoped transaction locking serializes updates and pruning.
- `DELETE /search-history {}` clears only the current owner's history. The client serializes a clear after its in-flight search writes and discards stale history responses. Metadata search/recommendation generation never implicitly writes search history.
- `GET /recommendations?limit=12` → `{tracks:[{track:Track,reason,basis:"likes"|"history"|"search"|"discovery"}],personalized:boolean}`. Limit1–50. This first implementation ranks canonical public candidates against **only the authenticated user's** liked artists, recent-play artists and explicit searches, excluding that user's liked/recent tracks and deduplicating stable IDs rather than titles. Up to two bounded anonymous metadata searches can expand candidates. It never resolves audio or calls an account source merely to generate a recommendation. `personalized=true` requires an actual interest-based result; generic fallback remains discovery. This is an explainable metadata baseline, not a claimed trained collaborative/audio model. No other user's private interests, popularity counts or history enter reasons.
- Trusted Bot code may call `RecommendForIdentity` only with an SDK-verified event's configured AppID, actual sender tenant_key and open_id. The lookup selects the exact existing Feishu account tuple; it does not create or infer accounts. No web cookie/admin Bearer is passed to the Bot. HTTP recommendations always derive their identity from `s.auth`, never URL fields.
- Additive `script/sql/20261116_music_recommendations.sql` creates only `music_search_history`. Original identity/session/library SQL checksums remain unchanged.

## Copy a public NetEase playlist

`POST /imports/netease-playlist {urlOrID,name?}` → `{playlist:Playlist,imported,duplicatesSkipped,sourcePlaylistID}`. The request is authenticated by the current music session and always creates a new playlist owned by that account. Existing playlists are never overwritten. The existing versioned JSON import/export is unchanged.

Accepts a numeric playlist ID or full official `music.163.com` / `y.music.163.com` playlist link, including the common `#/playlist?id=...` form. The server parses only the ID; it never fetches the supplied URL, follows short-link redirects, or treats URL userid/open_id as identity. Short links return400 `netease_playlist_full_url_required`; invalid IDs/hosts/userinfo/path return400 `invalid_netease_playlist`.

The import provider reads only fixed `/playlist/detail` and batched `/song/detail` paths through the configured trusted catalogue adapter, with **no operator Cookie or cookie jar** and no account fallback. Public metadata has an18-second overall deadline, batches of at most50 tracks and at most4 workers. All track IDs and complete canonical metadata must match the request. At most1000 original entries are accepted; over-limit import returns413 `public_playlist_too_large` without silently truncating, even if deduplication would make it smaller. Stable IDs are deduplicated in first-occurrence order. Metadata, new playlist and entries are persisted in one transaction after all metadata succeeds; failures leave no partial playlist or shared-catalogue writes.

Private/restricted playlists return403 `public_playlist_access_denied`; missing/incomplete metadata422 `public_playlist_metadata_incomplete`; empty playlists422 `public_playlist_empty`; source failure503 `public_playlist_source_unavailable`; missing configured importer503 `public_playlist_import_not_configured`; explicit rate limiting429 `provider_rate_limited`. These are never an instruction to log into NetEase in the browser or borrow the operator's private playlist visibility.
