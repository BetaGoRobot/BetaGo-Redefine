# Conversation Callback Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立 PostgreSQL 持久化的轻量 Conversation Runtime，并完成 `edit_schedule` 从发确认卡、用户点击、幂等执行到 Agent 续接回复的首个端到端闭环。

**Architecture:** 复用现有 `agent_sessions / agent_runs / agent_steps`，把群级 session 作为长期容器、run 作为一次激活周期、queued step 作为 durable inbox。现有卡片继续走 V1 registry；只有携带 runtime envelope 的新卡片进入 V2 continuation dispatcher。PostgreSQL负责状态、claim 和幂等，OpenSearch 通过 outbox 接收最终一致的事件投影。

**Tech Stack:** Go 1.25, PostgreSQL, GORM Gen, OpenSearch Go v4, Lark Card JSON v2, existing `runtime.Executor`, Ark Responses API, Go testing

---

func HashInteractionToken(token string) string {
    sum := sha256.Sum256([]byte(strings.TrimSpace(token)))
    return hex.EncodeToString(sum[:])
}

func MatchInteractionToken(token, hash string) bool {
    got, err1 := hex.DecodeString(HashInteractionToken(token))
    want, err2 := hex.DecodeString(strings.TrimSpace(hash))
    return err1 == nil && err2 == nil && subtle.ConstantTimeCompare(got, want) == 1
}
