# 梗知识前置设计：伴随验证记录

日期：2026-10-30。对应[设计稿](../superpowers/specs/2026-10-30-meme-knowledge-first-design.md)。本文明确区分现链路证据、离线契约原型、实际模型样例和待执行验收。

## 1. 本轮结论

有证据支持“先用原文字面信息找背景，再让模型解释和扩召”的方向；还不能判定整套设计通过。

新增验证完成了 33 项离线原型检查，以及当前规划模型的 4 个结构化样例。四次模型调用均返回有效结构和有效引用编号，但其中一条知识关联查询缺少知识引用，被条件校验拒绝；认真游戏问题仍有过度联想，盲盒续接仍没有形成竞争解释。后续必须验证意图消歧、全链路扩召和最终表达。

本轮没有修改生产源码、激活语料、写入梗卡或索引，也没有向飞书发送测试消息。模型探测通过既有配额门和时限，可能更新模型配额记录。实验代码位于独立缓存目录，不能当作生产实现或正式回归套件。

## 2. 输入与对照

私有证据目录：`/mnt/RapidPool/build-cache/meme-knowledge-design-20261030/`。

- `evidence/input-manifest.json` 记录上轮输入文件的 SHA-256，原始文件继续保留于 `meme-hell-cases-20261030/`。
- `evidence/lexicon-subset.json` 从冻结原生索引读回中整理出 309 个词条，涉及 1,264 次 raw 命中。它是有界读回子集，不是 6,683 个来源或 36,836 条用法的完整代际词典。
- 公共原型只用词条标题做主要匹配，没有把模型推断别名自动当作确定别称。校长多义、跨群和兼容字形等契约使用明确标记的合成夹具。
- 模型样例使用 H03、H05、H04、R02：原话/回复关系来自已见开发材料；H03/H05 实际匹配到同一个海岛奇兵词条，H04/R02 没有在该子集匹配到字面知识。没有人工塞入目标笑话或新增原文。

这些案例与新写的契约用例都已经被设计者查看，不属于幽默质量留出集。

## 3. 复用的现链路证据

上轮已执行 10 个案例的原生读回与 19 格原生回放，首轮回答共 23 次模型调用，保持完整 74 项工具替身。回放前冻结时钟与角色，并验证每对输入只改变梗参考卡。语料代为 `wd_054b77808e07`，首轮召回 9 次 ready，H06 规划阶段超时一次；原始失败保留。

| 实验 | 观察 | 可以说明的范围 |
| --- | --- | --- |
| 原生 H03 | “硬核策略转休闲手游”；海岛奇兵被前二关键词预算丢弃 | 理解偏差与关键字丢失确实发生 |
| 同模型普通问答 H03 | 仍顺着游戏越玩越简陋接话 | 参数先验在该次输入下不足以稳定识别历史影射，不能只归因严格查询提示词 |
| 整句 BM25 前置 H03 | 23ms，得到多个无关词条 | 前置搜索需要片段选择；整句前置不自动改善知识 |
| 原词名字面预检索 H03 | 6ms，找回三张海岛奇兵用法 | 已知名字可在规划模型理解前触达背景 |
| 同词游戏本义 H05 | 10ms，得到同一历史梗词条；规划仍能查询游戏/雷达 | 词条存在不能直接决定义项，也不必然导致强行玩梗 |
| 冻结分析，只调 H03 关键词次序 | 查询及候选预算不变，找回海岛奇兵卡 | 字面锚点应独立保留；该手工调整不是通用算法已实现 |

6/10/23ms 均为少量热路径样例，排除了词典冷加载等成本，不能作为整库 P95 或上线性能结论。旧回放只是结构与行为观察，没有真人好笑率或胜率。

## 4. 新增契约原型：33 项

代码与结果分别在 `prototype/validate_design.py`、`prototype/validation-results.json`。运行方式：

```sh
python3 /mnt/RapidPool/build-cache/meme-knowledge-design-20261030/prototype/validate_design.py
```

这个原型用于检查设计契约是否可表达、能否拒绝明确反例；没有接入生产 PG 发布、完整词典、真实 NER/POS、多轮规划或主回复生成。

| 用例 | 检查内容 | 结果 |
| --- | --- | --- |
| C01–C03 | H03/H05 相同词条背景；第一层不提前选择义项 | 通过 |
| C04–C05、C17–C18 | rune 原文区间、emoji、兼容字形、拉丁词边界 | 通过 |
| C06–C08 | 对话指令噪声、两字“微操”、“机器人春晚”不能按停用词误删 | 通过 |
| C09–C10、C13–C14、C33 | 无命中与快照/记录代际一致性 | 通过 |
| C11–C12、C15 | 扩召为空/无关时知识仍保留，原文不改写 | 通过 |
| C16、C20–C21、C31 | 同名歧义、词典顺序和关键词六种排列 | 通过 |
| C19 | 六个锚点上限与明确遗漏计数 | 通过 |
| C22–C27、C32 | 字面/知识/假设来源、非法引用与全局七查询预算 | 通过 |
| C28–C30 | 跨群可见范围、同群材料、消息编辑后的身份 | 通过 |

其中 C21 的六种排列是同一输入的变形验证，不能算六个新语义案例。兼容字形原型采用逐码点转换及位置映射，没有实现通用跨码点规范化，也没有证明全语言分词正确性。

### 反证带来的设计修正

初版 30 项通过后，增加反证，出现 3 项失败；保留于 `prototype/validation-red.json` 和 `validate_design_red.py`。修正后 33 项通过。

| 发现的问题 | 修正及设计要求 |
| --- | --- |
| 同名义项顺序跟随词典遍历顺序 | 义项引用稳定排序，模型不应因地图遍历顺序得到不同的隐含优先级 |
| 原型校验曾信任查询自报的 `literal_source` | 改用服务端冻结观察表；正式 literal 查询直接由服务端原文引用生成 |
| manifest 头代际正确，但词条本身可混入另一代 | 校验每条记录的代际，不能只看快照头 |

这些是本轮离线原型的缺陷和修正，不是已经定位并修复的生产缺陷。

### 微基准

在 309 词条子集上做 100 次热内存扫描，最后一次记录 P95 约 1.38ms。该值不包含完整代际词典、PG、Milvus、冷启动、模型或并发压力。只能说明该有界原型可运行，不能替代设计要求的完整环境性能基准。

## 5. 新增实际模型验证：4 个样例

使用当前规划模型 `deepseek-v4-1-flash-economy-261017`，经现有 `memeQueryCompletion`、共享配额门与模型 HTTP 适配调用。沿用 8 秒模型期限和 12 秒请求期限，未重抽取优、未做结构修复。测试程序退出成功只表示采集完成，逐例结果另行校验。

首轮背景为实际字面匹配得到的原始 Wiki 释义，保留来源属性为 `wiki_usage_explanation` / `source_claim_not_verified_history`。输出契约要求最多两个有依据的解释和两个有用途的查询，不写最终群回复。

| 案例 | 调用耗时 | token 输入/输出 | 结果与限制 |
| --- | ---: | ---: | --- |
| H03：钢铁雄心→海岛奇兵 | 5472ms | 1186 / 389 | 保留游戏变化、历史影射两种解释；产生海岛奇兵字面查询，以及有知识引用的关联查询 |
| H05：认真问雷达升级 | 4693ms | 1202 / 375 | 主解释为游戏问题；仍追加牵强影射解释，且一条 knowledge_link 无知识引用 |
| H04：公会只剩小岛仍喊反攻 | 2032ms | 865 / 93 | 看出“败退仍嘴硬”的调侃请求；未扩召，未验证结构类比能否迁移为好句 |
| R02：除了委员长，盲盒还有什么款 | 2160ms | 1267 / 113 | 只解释为真实款式问答，没有表示玩笑续接；该缩短窗口本身没有唯一意图金标准，需补全可见语境并人工标注 |

结构校验结果：4/4 返回符合该原型约束的对象；4/4 引用编号属于输入。四条实际查询中三条满足来源条件、一条被拒；H04/R02 均没有提出查询。按案例计为 3/4 的全部查询满足条件，但该分母包含两例零查询，不能用来估计查询准确率。H05 的一条查询被独立条件校验标记 `knowledge_link_without_knowledge_reference`，不会因字段名写了 knowledge_link 就放行。

这次较丰富的规划输出使用了更多输出 token 和时间。样例仍在现有期限内，但不能据此保证扩召也能在剩余总预算内完成，或保证比现链路更快。

### 尚未通过的语义要求

1. 存在梗义时，不能为认真本义问题制造没有新证据的第二解释。多义需要支持/反证，不能变成“凡事皆可影射”。
2. 查询 origin 与引用之间需要条件校验；编号有效不代表该编号支持当前含义。
3. 未决问题应当与理解/表达有关，不把“机器人身份、损人尺度”等无关缺失自动变成用户追问。
4. 当前原型不能证明盲盒场景的语用续接已解决，也没有生成新的最终群回复或真人盲评。

实际输入、输出、校验和构建证据在 `model-probes/planner-input.json`、`planner-results.json`、`validation-results.json`、`build-proof.json`。原始输入可能包含本地历史窗口，只存私有目录；不导出原始用户标识到公共夹具。
