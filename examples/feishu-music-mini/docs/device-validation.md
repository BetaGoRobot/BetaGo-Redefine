# Android / iOS 真机执行表

当前所有行均为 **PENDING**，见 `device-results.csv`。没有使用 Persona 手机工具操作飞书 UI，没有真机截图、锁屏结果或线上播放证明。

## 开发者操作入口

你是应用开发者，可在自己的电脑上按照 [developer-quickstart.md](developer-quickstart.md) 登录开发工具、导入并生成**手机可扫码测试预览入口**。需要确认现有应用实际允许小程序、请求/音源/网页跳转的既有测试 HTTPS 域名可用。代理运行环境没有你的开发者登录态或可操作的飞书真机；官方预览依赖登录和正确 App ID，因此不能由 Node/HTTP 测试替代。无需发布线上应用，不创建付费资源，不要求授予 Hook 信任。

本目录已准备代码、校验包、32 分钟合法音源、可控过期服务、配置模板和以下步骤。App ID 请从你有开发权限的应用后台复制；不把本地应用配置带入公开工程，也不由代理修改应用权限。

## 在已有测试入口准备夹具

1. 解压源码/夹具包，执行 `npm ci --ignore-scripts && npm run fixtures:generate`（音频包已含 WAV 时可跳过生成）。
2. 在现有测试 HTTPS 入口代理 `127.0.0.1:8787/fixture/*`，支持 Range，不缓存带 lease 的测试音源。不要代理到生产歌单服务。
3. 使用对应 `FIXTURE_PUBLIC_ORIGIN=https://<测试源>` 启动 `npm run fixtures:serve`。先用浏览器验证 `/fixture/health`，应显示 `nativeDeviceProof:false`。该检查只是服务连通性。
4. 复制 `config.example.json` 为 `config.local.json`：填测试应用 ID、`mode:fixture`、测试 HTTPS 源和 `audioOrigins`，网页回退配置已部署的自有网页地址。`allowLocalhost:false`。
5. `npm run verify`；保存 build-report 中的哈希。导入 `dist/` 或解压开发包。开发者工具执行官方编译并保存编译日志；若失败记录失败，不能沿用静态校验结果声称编译成功。
6. 维护者在开发工具中点击“预览”，用 Android/iOS 飞书扫码。同账号/应用可见范围/请求域名不满足时记录具体阻塞；不擅改线上权限。也可在已有官方 CLI 登录态下使用 `opdev preview ./dist --platform=mobile`。本任务没有运行该预览命令。

## 逐项执行

每部设备记录：实际设备型号、OS 完整版本、飞书版本、SDKVersion、原型 commit/开发包摘要、网络类型、Android 省电策略、执行者、当地时间。先连服务，确认队列出现 A/B 两曲，连接后应保持暂停，点击播放才开始。

| 编号 | 操作 | 通过条件/必须留存的观察 |
| --- | --- | --- |
| FG | A 播放30秒；暂停5秒再播放；seek到2:00和8:00，前后切A/B | 曲目/队列下标一致；恢复位置误差不超过3秒；无叠播；记录首次播放延迟 |
| CHAT | 播放30秒，返回聊天并切到另一会话，等2分钟再回原型 | 无人为停止；返回时进度前进约2分钟；App/页面隐藏事件与声音观察同时记录 |
| CARD | 从聊天入口打开原型并播放，让原入口卡片彻底离屏；等2分钟 | 原型播放不依赖入口卡片视图；不是测试卡片 native audio 本身；记录卡片是否更新 |
| BG | A 从0:30开始，飞书退后台5分钟，再返回 | 无明显停止；返回进度约5:30；后台 JS 进度日志缺口单独记录 |
| LOCK15 | 新一轮A从0开始，锁屏连续15分钟；不解锁观察声音/播控 | 15分钟持续可听；解锁进度约15:00；记录锁屏控件和实际声音，不能只看JS计时 |
| LOCK30 | 新一轮A从0开始，锁屏连续30分钟，跨16:00自动进入B | 最终B约14:00；从A到B无手工唤醒；记录换曲时长、网络取源是否执行 |
| NEXT | A seek到15:40，立即锁屏；过70秒再解锁 | 自动进入B约0:50；锁屏下一曲取源成功；与LOCK30分开记录 |
| EXPIRE | 播到2:00，保存旧夹具URL供本机探测；点击“使已签发URL过期”，seek未缓冲位置或等待下一次媒体请求 | 旧URL返回403；只有收到原生onError后自动resolve才算自动恢复；新URL恢复本次最后确认位置，误差≤3秒；禁止用手动“刷新续播”替代自动结果 |
| EXPIRE-PAUSE | 播2:00暂停，撤销URL/等TTL过期，等70秒再点播放 | 新resolve，位置从约2:00恢复，不复用已过期URL；此项与播放中出错刷新分开 |
| CALL | 播放中用另一电话呼入，接听20秒后挂断，观察后点播放 | 记录系统实际暂停/混音/恢复行为；若暂停，用户恢复取新源且位置正确；不自动抢夺音频；可记录“需手动恢复” |
| OTHER | 播放中打开其他音频/视频，播放20秒，返回原型 | Android记录暂停/iOS记录是否混音；用户恢复后仅一个音源，位置正确 |
| COLD | 暂停3:00并等待进度保存，关闭测试小程序再打开并连接 | 自有队列恢复为暂停，位置约3:00；点击后新resolve；无从卡片读取进度承诺 |
| FALLBACK | PC/不支持容器打开；点击固定网页入口；目标白名单未配时重测 | 背景音频显示不可用；HTTPS网页能打开或明确失败；不跳未知schema、不泄露token |

暂停/seek的误差阈值是本原型的验收目标，不是官方保证。LOCK30若失败仍保留实际结果与网页入口，不把单曲可播改写成长队列成功。来电后系统自动恢复与手动恢复分别记录，不能混记。

## 记录与导出

每完成一项点击“复制脱敏诊断”，存到受控的测试证据目录。公开记录只引用经检查的脱敏文件；手机截图隐藏个人聊天、联系人、二维码与账户信息。

CSV 中用 `PASS / FAIL / BLOCKED / PENDING`，填实际位置、声音是否中断、是否触发原生事件、截图/诊断文件、失败原因。不要把 Node 测试复制成CSV的PASS。接口探针结果同样不代表设备成功。

若遇资源过期且播放器已完整缓冲，旧URL403与声音仍继续是可能结果；记录为“未触发新媒体请求”，不能伪造恢复事件。可重启该项、限制网络缓存或选择未缓冲位置；仍不能触发则EXPIRE保持待验证。
