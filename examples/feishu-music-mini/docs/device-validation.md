## 测试前由维护者准备

普通测试复用真实 API 和现有 MinIO 歌曲。应用开发者按 [developer-quickstart.md](developer-quickstart.md) 登录开发工具、导入维护者提供的已配置 ZIP、预览并扫码，无需启动测试服务或修改服务器网络。

API 来源是 `https://music-mini.kmhomelab.cn:2443`，音频实际来源是 `https://music.kmhomelab.cn:2443`，开发包必须同时正确配置两者。两首指定歌曲已经通过真实 API 返回 `available`、`owned_minio_cache` 并取得 HTTPS Range 206，缓存部署阻塞已解除。当前 `/auth/options` 的 `feishu.enabled=false`，使用自有访客登录。域名已知有 AAAA 记录，手机网络连通性仍待验证。

维护者交付手机测试包前应完成：

1. AppID已由官方只读接口核实。发布版本未返回小程序能力，未版本化开发配置、测试账号范围与域名许可仍需开发者登录工具后确认；保持正常校验，不擅自修改应用设置。
2. 将已通过服务端检查的真实 API 和音频来源配置进开发包；不以手工拼接对象地址替代解析接口。
3. 选出现有的至少两首歌曲，核对可完整播放与实际时长，准备总时长**大于 30 分钟**的本设备播放列表。
4. 构建默认 `service` 模式的已配置 ZIP，提供包摘要与歌曲说明。16 分钟合成音只供本机回归，不部署为公网手机测试音频服务。
5. 在开发工具执行官方编译和预览，保存真实结果；编译或扫码失败时记录阻塞，不沿用静态校验声称成功。

## 逐项执行

每部设备记录：型号、OS 完整版本、飞书版本、SDKVersion、原型 commit/包摘要、网络类型、Android 省电策略、执行者、当地时间。先连接服务，搜索并选择指定歌曲，确认已有列表保留、新歌曲追加；需要建立长测列表时先暂停并按计划加入歌曲。连接本身应保持暂停，用户选择歌曲或点击播放后才开始。

下表的 A/B 是经维护者确认的实际歌曲，不是固定 16 分钟合成音；起始位置和预期曲目按播放器运行时显示的时长计算。

| FG | A 播放 30 秒；暂停 5 秒再继续；拖动到约 20%/60% 位置，前后切 A/B | 曲目/列表下标一致；恢复位置误差不超过 3 秒；无叠播；记录首次播放延迟 |

## 过期测试与结果记录

`service` 模式没有测试服务的“让当前播放链接过期”按钮。实际链接过期检查由维护者安排，或等待真实有效期；若无法安排，EXPIRE 保持待测。维护者的对象链接探测 206 → 403 → 206 只证明服务端行为，不能写成手机自动恢复成功。

若播放器已经完整缓冲，旧链接返回 403 而声音继续是可能结果。记录“未触发新媒体请求”；可重新执行并选择未缓冲位置，仍未触发则保持待测，不补写恢复事件。

每完成一项点击“复制排查信息”，保存到受控目录。公开记录只引用检查过的文件；截图隐藏个人聊天、联系人、二维码和账户信息。CSV 使用 `PASS / FAIL / BLOCKED / PENDING`，填写实际位置、声音是否中断、原生事件、证据和失败原因。Node 测试与接口探针均不能直接写成设备 PASS。
